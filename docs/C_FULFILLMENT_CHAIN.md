# 同一订单的自动交付链路核验

新增隔离检查 `scripts/test-fulfillment-chain.mjs`，把同一订单贯穿结账、服务器签名付款事件、精确内容权益、通知队列、账号下载及退款确认。与既有单模块检查配合使用，避免手工插入一条“已付款”记录后就把后续步骤当作完整交付。

检查执行实际服务端模块、私有 schema 与受限运行角色的 PostgreSQL SQL、Stripe SDK 签名校验，以及 R2 适配器的完整 SHA、条件 ETag 和文件字节读取。数据库在本机隔离；Stripe 商户资源、R2 对象和邮件提供者都是明确的内存 fixture，外部网络被阻止。fixture 的商品、税率、费用和账号不代表任何真实商业配置。

核对重点包括重复事件不重复发权益或邮件、短时链接仍需当前账号和有效权益、完整退款确认后旧下载链接不能读取对象，以及退款前尚未发送的购买通知不能发送。独立订单的访问不能被另一个订单的退款误撤销。邮件只链接到需登录的账号页面，不包含对象位置或文件授权。

提供者接受邮件不等于邮箱收到邮件。退款前已交给邮件提供者的消息可能后来才到达，应用不能撤回该消息；账号在每次下载时仍会重新核验当前权益。提交退款后、尚未完成权威商户资源对账期间，原权益暂保留。再次对账已成功的完整累计退款不会重复创建退款；只有确认完成后才撤销该订单的权益。

该检查不执行真实 Stripe sandbox/live 交易、商户官方 webhook 投递、Cloudflare 文件读取或客户发信，也不证明线上跨服务压力与送达。常规运行入口为 `npm run test:fulfillment-chain`；实际结果及文件 SHA 另存于私有交付回执。已有 198 项检查保留各自版本和时间，不能与新增检查相加后冒称整套重新执行。

本次仅新增检查和说明，不修改价格、真实商品、税务事实、销售开关、Secret、部署、正式域名或流量。真实测试商户的结账、退款、私有下载及购买邮件验收仍是独立的后续步骤。
