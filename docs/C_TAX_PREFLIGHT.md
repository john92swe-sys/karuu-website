# 扣款前证据核对：只读适配层

`tax-preflight.ts` 新增原订单／成本／地区政策的版本指纹，读取商户 Session、完整分页的税务登记和明细，以及 PaymentIntent／Charge 授权证据。它比较实际账单地址与原报价，再调用可信的服务器地区／VAT 领土解析器；国家码允许不代表该领土已获批准。

读取期间订单、成本或地区规则改变，原指纹即失效。分页重复、停滞或超过上限不会被静默截断。只有未扣款、金额完整、模式匹配、尚未到期的手动银行卡授权，才能得到“证据已核对”的诊断结果。完整税分类、实际登记、成本目标与税务预算仍需通过原校验。授权税明细带有单独的阶段标记，不能冒充已付款的不可变税收据；原 `verifyAutomaticTaxReceipt` 仍严格要求已付款状态。

本适配层**没有创建、扣款、取消、退款、权益或通知写接口**，所有成功结果仍为 `executionPermitted:false`、`paymentAction:none`。端口由可信服务器构造，不接受客户提供的“已批准”断言。当前没有公开接口，没有接入现有 Checkout 创建路径，也没有向真实数据库应用 v3 迁移。

后续仍需从受限数据库实际读取并存储原快照、验证当前商户支持及受限权限、建立授权／扣款操作状态和幂等写入、锁内核对原订单、扣款前重新读取商户资料，再在已确认扣款后一次写入最终税收据。读层的“通过”不是可重复使用的扣款许可，也不解决读取结束后与未来扣款之间的竞态。发卡行的资金预授权本身也是实际支付操作，本次没有发起。

`scripts/test-tax-preflight.mjs` 使用实际适配层及税务校验函数，所有商户资源和读端都是隔离内存 fixture，无外网和数据库写入。新增检查覆盖：完整分页仍关闭执行、地址改变、未知领土、读取期间成本／订单／政策版本改变、授权金额不足／到期／自动扣款方式／环境不符／已捕获、异常分页、旧数据库及错误商户范围，以及未付款资料不得通过已付款收据校验。运行入口为 `npm run test:tax-preflight`；数量、SHA、实际执行结果另存于私有交付回执。

原 198 项全量结果与原 6 项交付链路结果保留原源码和时间，本次只重跑与共用税数据校验相关的 18 项税务回归，不把各次结果相加冒称整套重新执行。未重新构建或部署，五个商业门、价格、Secret、税务登记、生产流量及真实商品均未操作。

参考：[Checkout Session 状态](https://docs.stripe.com/api/checkout/sessions/object)、[PaymentIntent 确认后的授权状态](https://docs.stripe.com/api/payment_intents/confirm)。SDK 字段和上述通用状态说明不证明当前商户的 Checkout、Tax 与手动捕获组合已完成实际验收。
