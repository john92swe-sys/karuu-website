# KARUU 官网方案 C 纠偏执行指令

你继续负责当前 KARUU 官网工程。本轮任务不是重新提案，而是把已确认的「C｜创意生活商店：桌面首页 + 手机首页」落实为真实可用的网站。

我随本指令附上两张图片：电脑实拍图是不合格的现状；带有「C｜创意生活商店」标题的桌面与手机组合图，才是目标视觉参考。

最终目标：让访客看到的是方案 C 的生活方式品牌商店，而不是目前白底、零散小图、细边框和大量空白组成的资料展示页。保留现有真实业务能力，让实体产品能产生询盘，让书籍、音频、音乐和游戏能通向实际内容。


一、先锁定正确工程与设计依据

读取当前窗口最新代码、工作目录、分支、未提交变更、素材目录、路由、构建脚本和部署配置。明确实际使用的框架、预览地址与正式站点，不能凭历史记忆猜测。

沿用当前工程，保存可恢复的修改前状态；不要覆盖其他窗口的未提交工作。允许为了方案 C 重做首页展示层，但优先复用现有业务逻辑，不为美化另起一套系统。

把方案 C 原图保存为项目内的设计参考，并分别识别桌面网页和手机网页区域。图片外的中文标题、外框和底部说明不属于网站内容。当前不合格版本只用于前后对比，不能作为新的视觉基准。

设计优先级：
方案 C 的明确视觉要求与本指令
> 已确认的品牌资料与真实业务数据
> 工具的一般审美建议。

不要重新提出 A/B/D 方案，也不要以「更高级」「更简约」为理由另做一种风格。

如果执行环境确实无法读取附件，准确指出缺失的是哪张参考图；可以继续工程核验，但不能声称已经按图验收。

工具里关于「少用卡片」「避免浅紫色」「避免圆角」之类的一般建议，不能推翻方案 C 已明确采用的浅色分区、圆角内容卡和蓝色按钮。

只在有明确能力缺口时扩展搜索；不要把大量下载仓库、安装插件或整理资源目录当作主要成果。优先在项目范围内引入，保留现有配置，记录实际使用的版本或提交及应用位置。

免费且可用于本项目的资源可以直接推进；涉及新增付费订阅、购买素材或签约时才单独提出。安装不了某个可选工具时，使用已读到的设计方法和现有工具继续实现，不能因此暂停整个网站。


三、先把图片素材做到位

先检查项目、已连接素材库和已授权资源中的现有素材，建立每个区域的素材映射：首屏、运动服、杯壶、书籍、有声内容、音乐、游戏分别用什么文件。

首屏需要接近参考图的完整生活方式场景：明亮的湖水或海湾、远山、自然光、右侧运动女性，以及协调的杯壶元素；左侧留出可读的标题和按钮区域。

不要继续使用目前「粉色衣服局部图 + 拱形裁切 + 悬浮书封」的拼贴主视觉。运动服、杯壶卡片应有足够大的生活方式图或真实产品图，不能用小 Logo 代替产品展示。

先复用适合的已授权素材。确需补图时，可使用已具备授权的图像工具制作品牌氛围图，或选取许可明确的素材；记录来源与用途。没有可用图像生成工具时不要假装已经生成，可以用合适的真实素材完成构图。

品牌氛围图不能冒充实际在售产品的准确外观；产品详情仍应使用真实产品资料。书籍使用当前真实出版封面、书名和平台信息，不为追求草图外观擅自改已出版封面。游戏使用真实游戏画面，概念图则明确标注。

参考图里示意性的书封和照片可以替换，但必须保持构图、图片占比、整体明亮程度与排版关系。不能因为缺少原图就把整个界面降级为白底文字框。

文字、按钮、书名和导航必须是实际网页元素；禁止把整张方案 C 当作网页图片，再叠透明点击区域伪装实现。


四、桌面首页按方案 C 重做

A. 顶部导航

保留 KARUU 品牌标识，以明亮白色或接近白色的底色呈现。

按参考图组织 Physical products、Digital creations、About，并接回现有联系入口、搜索和已具备的账户等功能。导航高度、字重和间距要接近参考图，不做复杂后台式菜单。


B. 首屏主视觉

采用横向、较大面积的完整场景图，不是左侧大量白色空地加右侧几个小元素。场景延展到整个首屏内容区域。

主标题保持：
Products for life.
Stories to explore.

说明文字保持：
Physical products and original digital creations from KARUU.

左侧两个主要入口：
Explore products / Explore creations。

蓝色实心主按钮搭配浅色描边次按钮。人物主体在右侧，与场景融为一体；标题不能遮挡人物，也不能因遮罩太重让全图变灰。

参考图中的手写短句只作辅助装饰，不抢主标题。首屏高度按参考图比例控制，不要膨胀成几乎看不到下方内容的整屏海报。


C. 实体产品与数字内容双分区

首屏下方直接出现并排的 Physical products 与 Digital creations。比例接近参考图，避免在首屏与内容之间插入大段空白。

左侧 Physical products：
浅薄荷绿或类似浅色背景，两张较大的图片卡片，分别展示 Women's activewear 与 JKJ-Plus drinkware。使用真实可理解的业务说明，并保留 Explore activewear、Explore collaboration 和 Start a project 等有效入口。

右侧 Digital creations：
浅淡紫色背景，保留参考图的「两本重点书籍 + Books & audio 入口」展示关系。书封要清晰、大小协调，书名易读；相关按钮连接真实详情、平台页面或音频内容。

优先使用当前最新已确认内容，不把以前的制作中任务或过期进展重新写回网站。实体产品和数字内容都要有图片，不要把任一分区简化成文字清单。


D. Explore more creations

保留 Books、Books & audio、Music、Games 分类入口或标签切换，连接实际内容。

按参考图组织书籍预览以及音乐、游戏卡片，保持紧凑但不拥挤的排版。音乐和游戏需要有合适的视觉缩略图，不要仅放一个图标。

有真实试听、视频或试玩资源时接入；只有介绍页时，按钮应明确表示查看介绍，不能放一个无响应的播放按钮。内容尚未发布时如实说明，但不要让已有内容被「Coming soon」占位替代。


E. KRU 横条与页脚

保留参考图底部轻量的 KRU / Member benefits 横条布局与说明入口，不让它变成抢占首页的币价面板或交易广告。

具体权益文案按当前已确认业务填写，不凭草图新增未落实的奖励承诺。本轮不擅自改变现有账户、支付或 KRU 业务逻辑。

页脚保留真实公司信息、联系方式及现有必要页面入口。


五、手机端单独实现

手机端以方案 C 右侧示意为依据，不是简单把桌面页面缩小。

顺序为：
简洁导航 → 主视觉 → Physical products → Digital creations → 内容分类与列表 → 音乐和游戏卡片 → KRU 横条 → 页脚。

按手机构图调整首屏素材的裁切和文字位置，保留人物、场景和主要按钮；必要时使用独立的手机裁切图。不能照搬桌面裁切导致人物只剩局部，也不能让文字盖住面部。

实体产品区用紧凑的图片入口呈现；数字内容区保留可读的书封；音乐和游戏可以按参考图组成双列小卡片。标签切换适配窄屏，不允许页面整体横向溢出。

菜单、搜索、展开收起、内容切换必须能用触屏操作。按钮尺寸和间距要方便点击，正文不能为了塞进一屏而变得很小。


六、统一视觉与保留真实业务

视觉关键词：
明亮、清爽、自然、蓝白主色、薄荷绿和淡紫分区、有生活方式图片的创意商店。

从参考图提取颜色、字号、间距、内容宽度、图片比例和圆角规则，集中管理。保持标题、正文、按钮层级清晰，减少当前版本中过小的文字、过多的装饰性小标签、淡灰边框和无意义留白。

允许轻量悬停、点击和展开反馈；不要增加影响加载的全屏动画、复杂 3D 或自动播放背景视频。

保留并回归测试已有路由、内容链接、联系表单、询盘流程、真实业务数据与部署能力。KARUU 和 JKJ-Plus 保持各自业务边界，协作展示不等于混用客户资料或重写 JKJ-Plus 独立站。

参考图中的账户、购物袋等入口先与已有业务核对。有现成功能就接回；尚无对应能力时不要伪装可以使用，也不要为了外观另建完整交易系统。必要时采用可用的联系或询盘入口，并在差异说明中解释。

表单不仅要有成功提示，还应在可测试环境验证记录或回执。测试数据明确标记，不给真实客户发送测试消息，不触发真实扣款或交易。


七、执行顺序

先完成工程核验和回滚点，随后确定素材与方案 C 的结构、设计规则，立即进入代码修改。

第一段实质成果必须是「对齐方案 C 的首屏 + 实体/数字双分区」在真实浏览器中的效果，而不是又一份计划书。首屏方向正确后继续完成首页其余区域、手机端和相关内页一致性，不停下来反复询问是否继续。

每完成一个主要区域就打开网页检查，与参考图对照后修正；不能写完整站才第一次看真实页面。

完成后按既有授权部署到预览环境并回读验证，再按当前项目已有发布授权处理正式站。存在确切的认证或付费阻塞时，明确阻塞动作，其余可执行工作继续。

不能以已安装 Skill、构建通过、测试数量增加或部署成功替代视觉交付，也不能把预览站误报为正式站。


八、必须进行视觉与功能验收

至少检查：
1440×1000 和 1920×1080 的桌面视口；
390×844 和 430×932 的手机视口；
并检查更窄的 360px 宽度是否溢出。

保存真实浏览器的桌面和手机首屏截图、整页截图。将参考图中的对应网页区域与实际截图按相近宽度并排比较，不能直接拿包含中文标题和双端拼版的整图做像素比较。

逐项检查：

— 首屏是否恢复完整场景图、左文右人及两个清晰按钮，而不是当前的白底小图拼贴。
— 实体产品是否有足够大的服装与杯壶图；数字内容是否保留两本重点书与音频入口。
— 薄荷绿、淡紫色分区、蓝色按钮、图片占比、栏目顺序与视觉密度是否接近方案 C。
— 手机端是否按参考重新排布，文字可读、按钮可点、图片没有错误裁切。
— 搜索、菜单、内容切换、书籍外链、询盘及真实媒体入口是否按实际功能工作。
— 是否有断图、空链接、遮挡、溢出、加载后跳动或影响使用的控制台错误。

只要首屏构图、分区结构或手机布局仍明显不同，就继续修改，不得以「实现了同样的文字」判定完成。

方案 C 是概念图，真实照片和已出版书封不必像素相同；需要明确说明这些有依据的差异。不要编造「还原度 95%」「全部通过」等没有对应证据的结论。

功能测试与设计验收分别记录。新的视觉回归基线应建立在已对齐方案 C 的实际实现上，不能把当前不合格页面录成基线后宣布测试通过。


九、最终交付

交付能直接打开的预览地址，并准确注明正式站是否已更新；附桌面和手机的真实截图、修改前后对比，以及方案 C 对照。

同时给出修改文件和提交、实际应用的 GitHub 资源及作用、功能测试结果、仍存在的具体差异，以及修改前版本的恢复方式。资料保存到项目中，并写明真实文件路径。

最终说明以实际结果为主，不用大量安装日志充当交付物。对没有执行或没有核验的内容如实标注。
